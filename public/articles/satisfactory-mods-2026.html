SMMとSMLは別物

Satisfactory Mod Manager（SMM）はプレイヤーが触る管理Appで、MOD・依存関係・SMLを適切な場所へ配置します。Satisfactory Mod Loader（SML）はMODがGameへ機能を追加するためのLoader/API側です。公式Community documentationでは、SMLの更新もSMMが処理するため、通常ユーザーが手動でSMLを管理する必要はないと説明されています。

最初の導入は「Gameを一度起動」から

Documentationでは、先にSatisfactoryをTitle screenまで一度起動し、その後SMMを導入する流れが案内されています。SMMはGame installationを自動検出し、複数Installがある場合は対象を選べます。

MODを探すときはCompatible filterを標準にする

SMMにはAll Mods、Compatible、Installed、DependencyなどのFilterがあります。新しいMODを探すときはCompatibleが推奨されており、現在選択しているGame installに対応したものだけへ絞れます。古い動画で紹介されたMOD名をそのまま検索し、対応Versionを見ずに入れるより安全です。

依存MODは自分で一覧を暗記しない

MODが別MODやLibraryを必要とする場合、SMMはDependenciesを自動取得します。Trouble時に「自分が直接入れたMOD」と「依存として入ったMOD」を区別できることは重要です。Dependencyを手動で消すと、その上に乗るMODも動かなくなります。

2026年5月のSMM 3.0.7が示す重要なこと

GitHubのReleaseではSMM 3.0.7が2026年5月30日に公開されていますが、同じRelease noteで「この更新は1.2 ExperimentalでMODが使えることを意味しない。SMLはまだ作業中」と注意されています。Managerが最新版でも、GameのExperimental branchへLoaderが追いついているとは限りません。

大型Update当日の安全な順番

  1. 重要Saveを別名で複製。
  2. まずVanillaで起動できるか確認。
  3. SMM/SMLの対応Announcementを確認。
  4. CompatibleになったMODだけ少数で起動。
  5. 最後にGameplay/Content系MODを戻す。

Profileを用途で分ける

建築用、Vanilla寄り、友達とのMultiplayer用などでProfileを分けると、毎回MODを一つずつON/OFFする必要が減ります。問題が起きたら「最小Profileで起動→増やす」と切り分けできます。

Dedicated ServerでもMODは別問題になる

SMMはLocal/Remote Dedicated Serverも管理対象として追加できますが、ClientだけMODを入れてServer側がVanilla、あるいはVersionが異なると接続やGameplayに問題が出ます。Multiplayer用Profileは全員で同じ構成を共有する方が管理しやすいです。

アンインストールより先にPauseで確認

原因候補のMODを完全削除するとConfigurationや再導入が面倒になることがあります。SMMのEnabled/Disabled管理を使い、まず一時停止で症状が消えるか確認します。SaveへContentを追加するMODは、外すことでSave側に影響する場合があるためDescriptionを読みます。

MODが原因か分からないときの5分手順

  1. GameとSMMを終了。
  2. Debug infoとLogの保存場所を確認。
  3. 全MODを止めVanilla起動。
  4. 問題が消えたら半分ずつ戻す。
  5. 原因MODのDescription、FAQ、Issueを確認。

実際に壊れたときのケース別診断

ケース1：Game Update後、Title画面まで行かない

最初に全MODをDisableし、Vanillaで起動できるか確認します。Vanillaでも起動しなければMODではなくGame fileやDriverなど別原因の可能性があります。Vanillaだけ起動するなら、SMLと個別MODのCompatibilityへ戻ります。SMMのCompatible filterで現在のInstallへ対応していないMODを外し、最後に追加したものから戻します。

ケース2：MOD一覧には出るが機能しない

依存関係が自動取得されていても、MOD側に設定項目や特定のGame phaseが必要なことがあります。Descriptionを読み、設定Menu、Hotkey、必要Milestoneを確認します。古いVideoで紹介されたUIと現行版UIが違う場合もあるため、作者の現行説明を優先します。

ケース3：Multiplayerで自分だけ入れない

HostとClientでGame version、SML、MOD version、Profileが揃っているか比較します。「同じMOD名」でもVersionが違えば挙動が変わるため、Profile共有やScreenshotでInstalled一覧を照合します。Server側へ必要なMODが入っているかも確認します。

ケース4：Saveを開くと特定の建物だけ消える

Contentを追加するMODを外した可能性があります。そのSaveを上書きせず閉じ、Backupへ戻します。MODを再度Enableし、作者がRemoval procedureを用意しているか確認します。Gameplay dataを追加するMODは、UI MODと同じ感覚で抜き差ししません。

MOD構成を長期運用するなら「更新日」を記録する

数十個のMODを使うようになったら、Game version、SMM/SML version、主要MOD versionを簡単なTextで残すだけでも復旧が楽になります。動いている環境を毎回最新版へ追従させる必要はありません。大型Update直後は安定しているVersionを維持し、対応状況が揃ってから移行する選択もあります。

便利MODを選ぶ基準

「人気だから」ではなく、自分の作業時間のどこを減らしたいかで選びます。建築の反復を減らしたい、Inventory操作を楽にしたい、Logisticsを可視化したいなど目的を一つ決める。目的が重複するMODを複数入れるとUIやKeybindのConflictが増えます。

よくある疑問

SMMだけ入れればSMLも入る？

SMMが必要なSMLと依存関係を管理します。通常ユーザーがSMLを個別に手動管理する必要はありません。

Experimental branchでMODは使える？

SML側対応が終わっていない時期があります。Managerが最新版でも対応済みとは限りません。

Compatibleに出ないMODを無理に入れる？

Version指定機能はありますが、対応確認なしに強制するより作者のRelease noteを確認します。

Profileは何に使う？

Vanilla寄り、建築用、Multiplayer用などMOD組み合わせを保存して切り替えられます。

Dedicated ServerにもSMMを使える？

DocumentationではLocal/Remote serverをInstall一覧へ追加する機能が案内されています。

MODを外したらSaveが壊れる？

Content追加MODでは影響することがあります。作者説明とBackupを確認します。

SMMのLogはどこ？

GitHub READMEではLocalAppData配下のSatisfactoryModManager logsなどの場所が案内されています。

大型Update後に最初にすることは？

Vanilla起動とBackup確認です。MOD側の対応を待ってから少数ずつ戻します。

読み終わったら確認すること

  1. この記事の手順をそのまま暗記せず、自分のSave・PC・Versionで条件が同じか確認する。
  2. 一度に複数の設定を変えず、一つ変更して症状や結果がどう変わったかを見る。
  3. 更新で変わる情報は公式ページや配布元の更新日を確認する。
  4. 失敗した場合は最後の操作だけでなく、その前に何が不足していたかまで戻って考える。

うまくいかない時は、答えを探す前に状態を保存する

SatisfactoryのMODを2026年に入れる｜SMM・互換性・更新事故までのように複数の要素が絡むテーマでは、設定を何度も変えているうちに「何を変えたら直ったのか」が分からなくなります。問題が起きた時点で、Version、設定、MOD一覧、PC構成、表示されたMessage、直前の変更を一度メモします。Saveや設定Fileを複製できる場合は、変更前の状態を残します。

次に、原因候補を大きなカテゴリへ分けます。Game本体、設定、追加MOD/Tool、Network、Hardware/性能、Save dataのどれかです。全部を同時に疑うのではなく、最小構成へ戻して一つずつ足していきます。この方法は特定のGameだけでなく、MOD、Server、配信、VR、StorageのTroubleshootingにも共通します。

検索結果を読むときは「同じVersionか」を最初に見る

検索上位の記事や高評価Commentでも、書かれた時点では正しくても現在は前提が変わっていることがあります。投稿日、最終更新日、Game version、Tool versionを確認し、一次情報と矛盾する場合は公式の現行仕様を優先します。GameFinderでも、Communityの意見は「どう感じる人が多いか」「どこで詰まりやすいか」を知る材料として使い、仕様そのものの根拠には公式資料を優先しています。

最適化は、問題を再現できるようになってから

効率やPerformanceを上げる前に、まず同じ条件で問題を再現できるか確認します。再現条件が分かれば、変更前後を比較できます。逆に一度しか起きない問題に十個の対策を同時に入れると、改善したように見えても原因は分かりません。専門的な設定ほど、一回の大きな変更より小さな検証を積み重ねる方が確実です。

2026年8月の前提

2026年8月時点：Satisfactory Mod Managerは3.x系。GitHub Releasesでは3.1.0が公開済みです。

深掘り

SMMが更新された＝Game側MODが全部対応、ではない

2026年5月のSMM 3.0.7 Releaseでは、Manager更新が1.2 Experimental向けMOD準備完了を意味しないと明記されていました。6月の3.1.0ではUnreal Game Featuresを使うMOD管理への対応も追加されています。

ここから分かるのは、SMM、SML、各MOD、Game本体は別々にCompatibilityを見る必要があるということです。Managerが起動するだけでMOD Loaderや個別MODまで対応済みとは限りません。

深掘り

大型Update直後は「更新する」より「止める」判断が重要

長期Saveを守りたいなら、Game本体が更新された瞬間に全MODを追従更新する必要はありません。まずProfileとSaveをBackupし、SMLと必須Dependencyの対応を確認し、その後にQoL系から少数ずつ戻します。

壊れた状態で何度もSaveすると、原因を取り除いた後もSave側に変更が残ることがあります。MOD環境では『起動できた』より『同じSaveを安全に継続できる』ことを成功条件にしてください。

深掘り

ProfileはMOD一覧ではなく、用途ごとの復旧点

SMMにはProfile管理があり、建築用、Vanilla寄り、検証用などを分けられます。便利なのは切替そのものより、「このProfileなら昨日まで正常だった」という復旧点を持てることです。

大型MODを試す時は既存Profileへ直接足さず、複製Profileで起動確認する方が戻しやすくなります。Dependencyの自動導入は便利ですが、何が追加されたかを完全に見なくてよいという意味ではありません。

深掘り

MOD選びでは人気より、撤去可能性を見る

UIや表示だけのMODは比較的外しやすい一方、Item、Recipe、Building、World dataへ影響するMODは外した時のSave影響が大きくなります。長期Saveほど『面白そう』だけでなく『外す時どうなるか』を先に確認してください。

また、Game Update後に更新が止まったMODを代替へ置き換える場合も、旧MODを消して同時に新MODを入れるより、Backup上で旧構成を一度確認してから移行する方が切り分けやすくなります。

深掘り

2026年の実務的な導入順

初回はGameをVanillaで起動→終了→SMMを導入→必要最小限のMODだけ有効→新規Test Saveで確認→既存SaveをBackup→本番Save、の順が安全です。

Troubleが出たらMOD数を半分にして試すBinary searchが有効です。一つずつ無効化するより、大量構成では原因範囲を早く絞れます。ただしWorld改変系を無効にする時は、Test Saveで行い、本番Saveを上書きしないでください。

判断基準

MODは「便利そうだから全部入れる」より、役割で分けた方が壊れにくい。

UI改善、性能改善、操作補助、Content追加、Overhaulでは壊れ方が違います。まずQoL系だけで起動を確認し、その後に大型MODを追加すると、問題が起きた時に原因を戻しやすくなります。Version更新直後は『有名MODだから安全』ではなく、対応Versionと依存関係を確認する方が重要です。

失敗しやすいところ

一番避けたいのは、複数MODを同時更新して原因が分からなくなること。

Save互換、Loader、依存MOD、設定Fileのどこで壊れたのかを切り分けられない状態が最も復旧しにくいです。大型Update前はSaveと設定を分けてBackupし、変更は一段階ずつ行う方が安全です。
