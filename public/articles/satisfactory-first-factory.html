Satisfactoryを始めて数時間すると、他人の巨大工場を見て自分の地面置きコンベアが急に恥ずかしく見えます。そこでセーブを消す人すらいる。しかしCommunityを追うと、むしろ逆の助言が繰り返されています。初回のスパゲッティ工場を経験しないと、なぜ整った工場が便利なのか理解しにくい。

このゲームは完成品を展示する建築ツールではありません。足りないものを見つけ、ラインを追加し、詰まり、壊し、作り直す。その反復そのものがゲームです。

最初に覚えるべきは「比率」ではなく「流れ」

Minerが鉱石を出し、SmelterがIngotにし、ConstructorがPlateやRodに変える。Assembler以降は複数部品が必要になります。初心者が見るべき数字は、上流が1分あたり何個作るか、下流が何個使うか、Beltが何個運べるかの三つです。

機械が止まっているとき、原因は大きく電力不足、入力不足、出力詰まりに分けられます。まずここを見分けられれば、巨大な計算表を暗記しなくても工場は直せます。

Load BalancerよりManifoldが初心者に強い理由

複数機械へ材料を均等分配しようとすると、Splitterを何段も組んだLoad Balancerになりがちです。Manifoldは一本の主Beltから順番に枝分かれさせる方式で、起動直後は手前に材料が偏るものの、機械内部が満ちれば奥へ流れ最終的に安定します。

最近の初心者相談でも「早めにManifoldを覚えると拡張しやすい」という助言が多い一方、Factorio経験者などは均等分配を好むこともあります。どちらも動きます。GameFinderでは、正解の形より、後から機械を1台増やせる形を初心者向けの基準にします。

Foundationを解放したら「整頓」より「余白」を買う

Foundationの最大の価値は建物が真っ直ぐになることではありません。高さを揃え、後からBeltやPipeを通し、工場を階層化できることです。最初の工場で最も不足するのはIron Plateではなくスペースです。

機械をぎりぎりに並べるより、将来もう一列増やせる余白、Beltを横切らせる空間、上階へLiftを通す場所を残す。見た目の美しさはその結果としてついてきます。

序盤に「完璧な中央工場」を作らない

進行するとMiner、Belt、電力、Alternate Recipe、Blueprintなどが増えます。序盤設備を最終工場として設計すると、技術解放のたびに前提が崩れます。Communityで「restartするよりrebuild」という答えが強いのは、解体で資材を失いにくく、別のResource Nodeも多いからです。

最初のIron / Copper / Concreteラインを「建築資材を供給する仮設工場」と考え、Space Elevator進行後に必要に応じて専用工場を作ると気が楽です。古い工場は壊しても、博物館として残してもいい。

電力は「最大容量」より変動を見る

機械を増やして突然Breakerが落ちるのは、発電量が足りないだけでなく全機械が同時に動いた瞬間の需要を見ていないからです。Biofuel期は燃料補給そのものが作業になります。Coal Powerへ移ると燃料投入を自動化でき、ここで初めて工場の拡張速度が大きく変わります。

Underclockは初心者にも有用

Official WikiではClock speedを下げるUnderclockはPower Shard不要で利用でき、消費電力も低下します。上流が30/minしか供給できないのに下流が60/min要求するなら、機械を断続運転させるよりClock speedを合わせる考え方があります。

逆にOverclockは場所を節約できますが電力増加は線形ではありません。Wikiの例では200% clockで電力は250%相当。序盤で何でもOverclockすると発電所の拡張が先に必要になります。

何を中央に運ぶかに唯一の正解はない

全原料を巨大中央工場へ運ぶ方式、現地で中間部品まで作ってTrainで配送する方式、Item別専用工場を各地へ置く方式。どれも成立します。進行するほど輸送手段が増えるため、最初から最終物流を決める必要はありません。

初心者向けの実用的な順序

  1. Iron Plate / Rod / Screwなど建築で大量消費する物を自動化。
  2. Concreteを常時生産しFoundationを惜しまない。
  3. Assembler解放後はReinforced Iron Plateなどを少量でも自動化。
  4. Storage Containerへ余剰を溜める。
  5. Coal Powerへ進み電力補給を自動化。
  6. 物流が複雑になったら、全部直すのではなく次のラインだけ一段綺麗にする。

MODはゲーム版との互換性を見る

Satisfactory Mod Managerは依存Modの自動取得、更新通知、Profileなどを提供しており、現在のCommunity Mod導入では中心的なツールです。ただしSMLは非公式で、大型更新直後は対応待ちになることがあります。

Mod ManagerではCompatible filterが用意されています。大量に入れる前に、まずVanillaで起動、次に少数のMod、最後に便利系や建築系へ増やす方が不具合時の切り分けが簡単です。

結論：汚い工場を消す前に、一度眺める

Satisfactoryで上達を感じる瞬間は、最初から綺麗に作れたときではありません。20時間前の自分の工場を見て、なぜ詰まっているか説明できるようになったときです。初回工場には、その学習履歴が全部残っています。

Blueprintは「考えなくていい装置」ではなく、考えた結果を再利用する

Blueprint Designerを使えるようになると、Smelter群、Constructor列、Support、Belt junctionなどを再利用できます。最初から他人のBlueprintだけで組むより、自分が何度も同じ形を作った部分から登録すると、何を標準化したいかが明確です。

Blueprint化する単位を大きくしすぎると、Resource nodeやTerrainに合わせにくくなります。Machine数を固定した巨大Blockより、2〜4台単位のModuleや物流部品を作る方が融通が利く場合があります。

「100% Efficiency」はAchievementではない

Machineが常時100%動くことは設計の一つの目安ですが、建築材料を少量StockするFactoryや、需要が周期的なLineは止まっていても問題ありません。必要量を満たしているのにRatioを完璧にするためだけにFactoryを倍増すると、Powerと建築時間を使います。

効率表示は目的ではなく診断値です。Space Elevator部品を急いでいるのか、Storageをゆっくり満たしたいのかで「十分」の基準を変えます。

工場を見るときは、この4点だけ追う

供給Miner / Smelter
→
搬送Belt / Lift / Pipe
→
加工Constructor / Assembler
→
滞留Storage / 次工程

機械が止まる理由を「色」でなく数で読む

Lineが不安定なときは、機械の稼働率だけを見るより、Input/min、Output/min、Belt capacityを順番に比較します。例えば上流が60/minを出して下流二台が各30/minを要求するなら理論上は均衡します。そこへ三台目を追加すれば、三台すべてが時々止まる。故障ではなく、単純に供給が足りません。

逆に素材がMachine前で詰まっているなら、下流のOutputが捌けていない可能性があります。この「上流不足か、下流詰まりか」を一目で切り分けられると、工場が何倍に大きくなっても考え方は同じです。

PipeはBeltと同じ感覚で扱うと混乱する

Fluidは高低差やNetwork全体の状態が絡むため、Solid itemのように「一本に載せれば必ず順番に届く」と考えない方がいい。Pump、Head lift、Buffer、Machineの需要を分けて見ます。Coal Generator群でWaterが不足するときは、Extractor台数だけでなくPipeの経路、分岐位置、高低差、消費量を確認します。

Blueprintを使う前に、一度手で組む価値

Blueprintは反復建築を劇的に速くします。しかし最初から他人のModuleを敷き詰めると、なぜそのSpacingなのか、なぜBeltがその高さなのかが分からないまま規模だけが大きくなります。最初の一回は手で組み、二回目から自分のBlueprintへする方が、後で故障箇所を直せます。

MODは「便利」より「壊れたとき戻せる」を基準に

Satisfactory Mod Managerは依存関係を自動取得し、Compatible filter、Profile、Update通知を提供します。2026年5月公開のSMM 3.0.7でも、Experimental更新直後はSML側が未対応のことがあると明記されました。大型Updateの日は、Modを更新するより一度Vanillaで起動できるか確認する方が復旧が速いです。

よくある疑問

最初から効率100%を目指す？

必要ありません。まず自動化し、どこが不足するか観察してから比率を合わせる方が理解しやすいです。

Manifoldは損？

起動直後は奥の機械が遅れますが、入力が十分なら時間とともにBufferが満ちて安定します。定常状態で判断します。

工場を全部一か所に集めるべき？

唯一の正解はありません。序盤は近い資源ごとに小さく作り、輸送手段が増えてから統合方針を決めても十分です。

古い工場は壊す？

解体で資材を回収できるため、作り直しやすいゲームです。残したいなら建材供給工場として使う方法もあります。

MODは一周目から必要？

不要です。Vanillaを理解してから「何が面倒なのか」が分かった時点でQoL MODを選ぶと効果を判断できます。

Overclockはいつ使う？

土地や機械数を減らしたい場面で便利ですが、電力増加も見る必要があります。序盤はUnderclockも有効です。

読み終わったら確認すること

  1. この記事の手順をそのまま暗記せず、自分のSave・PC・Versionで条件が同じか確認する。
  2. 一度に複数の設定を変えず、一つ変更して症状や結果がどう変わったかを見る。
  3. 更新で変わる情報は公式ページや配布元の更新日を確認する。
  4. 失敗した場合は最後の操作だけでなく、その前に何が不足していたかまで戻って考える。
2026年8月の前提

2026年8月時点：Satisfactoryは1.2系。公式Wiki上の最新Patchは1.2.4.0（2026-08-11）です。

深掘り

最初の工場で完成させるべきなのは、建物ではなく判断手順

初心者が最初の工場で学ぶべきことは、綺麗なFoundation列や完全な比率表ではありません。「入力が足りないのか」「機械が詰まっているのか」「電力で止まっているのか」を見分ける順序です。

一台のConstructorが止まった時に、Beltを太くする前にInput Buffer、Output Buffer、Clock Speed、上流Machineの稼働率を見る。この手順が身につけば、規模が10倍になっても原因を追えます。逆に序盤から完成形のMega Factoryを真似すると、なぜ動いているかを理解しないまま複雑さだけ増えます。

深掘り

Manifoldが強いのは、最適だからではなく拡張時に考える量が少ないから

Load Balancerは美しく均等に分けられますが、Machine数が変わるたびSplitter構成を考え直しやすくなります。Manifoldは起動直後こそ末端まで満たす時間が必要でも、Lineを延長しやすく、Machine追加の思考コストが低いのが強みです。

ここで重要なのは「Manifoldこそ正解」ではありません。高価なItemを少量だけ正確に配りたい場面や、Space制約が特殊な場面では別構成が合理的です。初心者には、まず流量とBufferの関係を学びやすい方式としてManifoldが扱いやすい、という位置づけです。

深掘り

Factoryを建て直すTriggerを決めておく

序盤工場をいつ壊すかで時間を使いすぎるPlayerは多いです。建て直す基準を「汚く見える」ではなく、「物流が物理的に通らない」「電力・Belt tier更新で構成を変えたい」「次Phaseで入出力が大幅に増える」のような機能条件にすると迷いが減ります。

見た目が悪いだけなら、その工場はまだ役割を果たしています。古い工場を残したまま横に新Lineを作り、供給が安定してから切り替える方が、全面停止して再建するより安全です。

深掘り

1.2でVehicleが変わっても、物流設計の原則は変わらない

1.2ではVehicle周りに変更がありますが、2026年2〜3月のCoffee Stain側Q&Aでは、以前示唆されていたTrainの大きな新機能は1.2へ入らないと訂正されています。つまり「1.2だからTrain設計を全部待つ」という前提にはしない方がよいです。

物流手段は、距離、Throughput、地形、拡張性、燃料/電力、駅やRoadのSpaceで選びます。Truckが好きだから全輸送をTruck、Trainが強いから全部Trainではなく、短距離Belt・中距離Vehicle・大量長距離Trainなど役割で分けると複雑さを抑えられます。

深掘り

効率100%を目的にすると、遊びが止まりやすい

Satisfactoryでは100% Efficiencyを達成すること自体が目的ではありません。Outputが次工程の需要を満たしていれば、Machineが時々停止しても問題ないLineは多くあります。

特に初心者は、全Machineを常時100%にするためにOverbuildし、そのためのPower、Belt、Resourceを追加し、Factory全体を複雑にしがちです。最初は「必要量を安定供給できるか」を基準にし、余裕が出てからEfficiencyを詰める方がProgressionを止めません。

判断基準

配信・録画は画質より先に、音声と保存先を安定させる。

映像が多少粗くても見直せますが、Micが入っていない、Game音だけ極端に大きい、保存先が一杯で録画が止まる問題は後から直せません。最初に音量、Track、録画先、空き容量を確認し、その後でBitrateやEncoderを調整する方が事故が減ります。

失敗しやすいところ

設定を上げれば綺麗になる、とは限らない。

Encoder負荷、書き込み速度、回線、Game側GPU負荷のどれかが限界に達すると、設定値を上げた分だけDropや音ズレが増えることがあります。問題が出た時はResolution、FPS、Bitrateを同時に変えず、一項目ずつ比較してください。

症状を記録→最初に崩れた箇所を特定→一項目だけ変更→再現性を見る
